# Workflows and prompting techniques for AI-agent-made motion graphics (Claude Code / Cursor / Codex + Remotion, GSAP, HyperFrames, HTML)

Research date: 2026-10-19. Method note: the session's network proxy blocked remotion.dev, dev.to, substack, wireflow.ai and most blogs. Primary material was therefore read from GitHub (raw.githubusercontent.com): Remotion's own Agent Skills and docs source (remotion-dev/skills, remotion-dev/remotion/packages/docs), and several practitioner skill repos that publish their full prompts, review scripts and critic prompts. Blog claims that were only visible through search-result summaries are marked "(search summary, not read in full)".

## 1. How practitioners structure briefs / prompts

### Takeaway
The prompts that produce good results replace adjectives with numbers and constraints: exact size/fps/duration, a shot list with frame or beat ranges, one "hero move" per shot, hex palette with one accent, named easings/springs, an explicit BANNED list of the model's default looks, and a "show me the plan before you code" gate. Vague one-liners do work with a strong model plus a taste skill, but the published high-quality results all sit on top of a long brief or a skill that supplies one.

### Cited Findings
- Remotion's own skill example prompts are short and rely on the skill for best practice: `/remotion-create Make a promo video for a record store`, `/remotion-markup Create an animated title card using Inter.`, `/remotion-maps Animate a route from Los Angeles to New York and make the camera follow it.` — [remotion-dev/skills README](https://github.com/remotion-dev/skills); [Remotion docs: Agent Skills](https://www.remotion.dev/docs/ai/skills)
- Remotion's official coding-agent flow: `npx create-video --yes --blank my-video`, `npx remotion skills add`, `npm run dev` in one terminal, then start `claude`/`codex`/`kimi`/`opencode` in a second terminal and prompt. — [Remotion docs: Prompting videos with coding agents](https://www.remotion.dev/docs/ai/coding-agents) (read from [docs source](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/ai/coding-agents.mdx))
- NovusEdge "motion-lab" `directing-motion` skill makes the agent write `brief.md` before any code with every slot filled. Verbatim template:
  ```
  GOAL:    what the viewer should understand or feel, one sentence, about THIS subject
  OUTPUT:  engine + version, W x H, file types
  TIME:    seconds x fps = N frames; loop yes/no; BPM if cut to a beat (frames per beat)
  LOOK:    background, palette in hex with ONE accent, typeface/weight/size, materials with values
  LIGHT:   (3D) key / fill / rim: color, intensity, position
  CAMERA:  (3D) lens or fov, path with frame ranges and easing; never parked, never a free spin
  MOTION:  easings as cubic-bezier, springs as damping ratio + Hz, durations in frames
  SHOTS:   frame ranges; ONE hero move each; how each shot hands off to the next
  BANNED:  defaults this piece must not use (start from the list below)
  QA:      the frames to still (every shot boundary and hit), numbers to measure
  ```
  Its rationale: "Every decision left open in the brief is filled with the model's default look: dark backdrop, neon glow, purple-to-blue gradients, bloom, sparkles, particles, a turntable spin, everything centered and moving at once. Replace each adjective with a number before building." — [NovusEdge/motion-lab SKILL.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/SKILL.md). The skill credits [@flxrnc's motion lab write-up on X](https://x.com/flxrnc/status/2105311836190978392), which "published every prompt and follow-up behind three Opus-made animations" — [motion-lab README](https://github.com/NovusEdge/motion-lab)
- motion-lab example user prompt: "Make a 6-second seamless loop for my CLI tool's launch post. Square MP4 and GIF." → agent writes brief.md (goal, timing, hex palette, easings/springs as numbers, shot list with one hero move per shot, ban list), renders stills at shot boundaries, reviews them against the brief, then renders the clip. — [motion-lab README](https://github.com/NovusEdge/motion-lab)
- A full verbatim director's brief (Abubakr Chan, Cheerful launch film, Sept 2026) uses XML-ish sections `<inputs> <direction> <structure> <build> <gotchas> <start>`. Key excerpts:
  - `<direction> Dribbble-level UI motion. One shape, never cut: every state is the same element morphing its size, radius and color while its content swaps with a short blur. A cursor drives every change with real clicks and drags. Light warm-gray canvas, black and white components, one clean UI font (Geist). Springs everywhere, a tiny overshoot at most. ... Banned: bouncy easing, particle bursts, glows, gradients on UI chrome, mismatched icon strokes, dead time, anything that looks like a template. </direction>`
  - `<structure> 120 BPM, 7 bars, something happens on every beat. "Find creators" button → loader searching 350M+ profiles → check → dynamic island ... → toast "Deal signed · @mayamoves" → back to the button. </structure>`
  - `<build> ... Every style is computed from time inside seek(t): no CSS transitions, no timers, no state carried between frames ... Render with Playwright: 4 subframes per frame, blended with ffmpeg tmix for motion blur at 60fps. 7. Render one frame per beat before the full render. Fix anything off the grid, cramped or hard to read. </build>`
  - `<gotchas> Never put will-change on anything the camera scales or the text renders blurry. Text that swaps inside a morphing container needs its own enter and exit timing or it overlaps. Make the last frame identical to the first ... or the loop stutters. </gotchas>`
  - `<start> Ask me for the inputs, then show me the state list on the beat grid before you write any code. </start>`
  - Plus an "open creative licence" addendum: "I want you to be the director ... put attention to detail ... think out of the box, no constraints on and full creative control". — [AbubakrChan/product-launch-motion references/prompts.md](https://github.com/AbubakrChan/product-launch-motion/blob/main/references/prompts.md)

### Inferences
- A good house brief template for marketing videos = motion-lab slots + Every's marketing rules (hook first, product within 3 s, real UI copy, captions burned in, one end-card headline + CTA) + an explicit "plan/storyboard first, then stop for approval" instruction.
- References (videos) must be converted to stills/contact sheets (ffmpeg) before the agent can use them; text descriptions of references are weaker than frame grabs.
- XML-tagged sections (`<direction>`, `<structure>`, `<build>`, `<gotchas>`, `<start>`) are a reusable prompt skeleton; `<gotchas>` accumulates lessons from previous runs.

## 2. Render-and-review loops

### Takeaway
Agents can't watch video but can look at frames, so every serious workflow renders stills at shot boundaries/beats, tiles them into timestamped contact sheets, adds phone-size (≈360 px) views and frame strips around cuts, and reviews against a checklist — ideally by a separate critic subagent that never sees the code. Notes are written as "frame N: problem: number to change", 1–3 fixes per round, and only the named frames are re-rendered. Expect 2–7 rounds.

### Cited Findings
- Remotion render skill: stills via `npx remotion still`; multiple frames in one call: `npx remotion render [composition-id] out/frames --frames=0,30,90 --image-format=png`. — [remotion-render SKILL.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-render/SKILL.md)
- Remotion's own skill tells agents to open Studio immediately after scaffolding ("before building or editing the composition. Keep it open while you work so the user can watch progress and steer"), to use `npx remotion studio --no-open` + an in-app browser where available, to navigate to `/[composition-id]`, and notes "The Studio supports WebMCP tools." It also says: don't render unless the user explicitly asks ("Render the video", "Export", "Give me the MP4"). — [remotion-best-practices SKILL.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-best-practices/SKILL.md); [remotion-studio SKILL.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-studio/SKILL.md)
- motion-lab loop: `node lab/render.mjs anim.html --secs 6 --fps 60 --size 1080x1080 --frames 0,84,112,359 --out out/stills` (stills first), then full frames, then `bash lab/contact-sheet.sh out/frames 24 5x3 out/contact.png` (every Nth frame, stamped with frame numbers). Review steps each round: (1) describe each still in one sentence as a viewer would and compare with SHOTS; (2) "count what moves in each frame. More than one hero at a time is the most common failure"; (3) check every BANNED item, "including ones you added while fixing"; (4) `diff.sh` across the loop seam and every shot boundary — "Small pops (a few dozen pixels) are invisible on a contact sheet and obvious in a loop"; (5) "Write notes as `frame 84: <what is wrong>: <the number that changes>`. Apply one or two per round. Re-render only the frames the notes name." "Two to four rounds is normal ... 'it feels off' is not a note." — [motion-lab SKILL.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/SKILL.md)
- motion-lab "when a fix doesn't hold": render the frames either side (`--frames 83,84,85`), list every difference, change only the causing line; when a fix works and could recur, add it to the brief's render contract. — [motion-lab fixes.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/references/fixes.md)
- claude-motion review-loop: half-res draft render → one frame per timeline beat "0.3 s after it so motion has settled", tiled 4×2 with timestamps → checklist → zoom with `npm run sheet -- --from 3 --to 5 --every 0.2` to scrub a transition, or a single full-res still. Rule: "Never report a video as done without looking at contact sheets of the current render" and "Don't claim a fix you haven't re-rendered and looked at." Checklist covers: one focal point per frame; no unintended collisions "especially during transitions where an exiting and an entering element share space"; nothing within ~60 px of an edge; frame 0 is a real image ("it's the X thumbnail"); nothing clipped by masks; key message readable at phone width; text not moving while read; exits faster than entrances; only palette colors; transients on beat lines; −14 LUFS ±1, true peak ≤ −1 dBFS. — [claude-motion review-loop SKILL.md](https://github.com/whaleyxbt/claude-motion/blob/main/.claude/skills/review-loop/SKILL.md)
- In claude-motion's worked example, the agent's own contact-sheet pass caught a regression introduced by a retime: "the prompt bar hitting the outgoing title at 3.7 s". — [claude-motion example](https://github.com/whaleyxbt/claude-motion/blob/main/examples/01-effort/README.md)
- claude-video-studio builds a review kit per draft: contact sheets at 2 fps, a 360 px "phone" sheet, "fast" strips of 12 consecutive frames around cuts, a 9:16 safe-zone overlay (red = platform UI), key frames, metrics.json (loudness, cue sync, max gap). The `frame-critic` subagent (model: opus, tools Read/Bash/Glob) starts "You are reviewing a video you did not make ... Do not read source code", reads sheets first then at most 6 key frames, scores 8 criteria 1–10 with automatic caps, and outputs "Three worst problems (fix these, in order)" with testable fixes. "SHIP only when every score is ≥8." A problem still visible from last round "cannot score higher than it did then." — [frame-critic.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/.claude/agents/frame-critic.md)
- Real cost of that loop: "A polished 30-second film took about 14 hours and 7 critique rounds. Final renders take about 18–19 minutes per format on an M1 Pro." Advice: "Decide when polishing stops before round 1 ('3 rounds, or every score ≥ 8'). The critic will always find something." Main thread reads "at most ~6 full-resolution images"; sheet review is delegated to the critic (context hygiene). — [claude-video-studio README](https://github.com/rishabhsxn/claude-video-studio); [CLAUDE.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/CLAUDE.md). Output: [Habitmon 30 s launch film](https://youtu.be/bY-mj3FiPHg) and [vertical Short](https://youtube.com/shorts/qBd2Y9PzNY4).
- Every's skill: single-frame audit `npx remotion still <comp-id> out/test.png --frame 60` ("fastest way to audit"), then multi-agent review with 4 parallel critics — design/layout, text/readability (720p, contrast, truncation, typos), narrative/pacing (arc, earned duration, CTA strength), brand consistency — compiled into one revision plan. "After 50 renders, you lose the ability to see the video. Four parallel critics don't have that problem." — [EveryInc SKILL.md](https://github.com/EveryInc/product-launch-video/blob/main/.claude/skills/product-launch-video/SKILL.md)
- Every's feedback-to-fix vocabulary: "This text is cut off" → line-height/overflow; "This feels clunky" → timing, counter digit-flicker rate; "You invented this label" → real UI copy; "Hold longer here" → extend scene, keep animation timing; "A little long overall" → cut redundant scenes. — [same](https://github.com/EveryInc/product-launch-video/blob/main/.claude/skills/product-launch-video/SKILL.md)
- For HTML/GSAP pipelines, Playwright drives frame-exact capture: page exposes `window.renderAt(t)` / `seek(t)`, sets `window.__ready = true` after fonts/assets load, renderer serves over http (module imports fail under `file://`), `--scale 2` supersamples, `--subframes 4` adds motion blur. — [motion-lab SKILL.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/SKILL.md); [claude-motion README](https://github.com/whaleyxbt/claude-motion)
- A practitioner (search summary) renders stills from settled moments and mid-camera-move and builds contact sheets to check the whole film's rhythm, catching clipped text and inconsistent spacing; says Claude Code should not be the only judge of its own output. — [The Agent Architect](https://theagentarchitect.substack.com/p/claude-code-remotion-video-rendering)
- Anthropic's Claude Code best-practices guidance (via secondary summary) recommends a visual loop: give Claude a way to take screenshots, provide a visual mock, implement, screenshot, iterate until it matches. — [summary mirror](https://publish.obsidian.md/aixplore/AI+Development+&+Agents/claude-code-best-practices)

### Inferences
- Minimum viable loop for a marketing team: `npx remotion render <id> out/frames --frames=<shot boundaries> --image-format=png` → ffmpeg/ImageMagick tile with frame-number labels → Claude reads the sheet against the brief + checklist → numeric notes → re-render only those frames. Add a 360 px-wide downscaled sheet for phone legibility.
- A fresh-context critic subagent that only sees frames (not code) is the single most-cited quality lever; give it hard score caps so it can't be "charmed".
- Humans must still gate music/voice choice and final watch on a phone — agents only measure audio.

### Gaps
- No official Remotion doc found describing a contact-sheet review loop; this is practitioner convention. Did not find quantitative comparisons (e.g., quality with vs without critic).

## 3. Project setup that raises quality

### Takeaway
High-quality setups put brand and motion decisions in files the agent must read (CLAUDE.md house rules, brand/frame.md mirrored in theme.ts, motion number tables), provide a small primitives library (springs, text reveals, camera, counters, safe-zone/format helpers), drive all timing from one timeline file (often in beats), parametrise with Zod props for variants, and port the real product UI rather than inventing mockups.

### Cited Findings
- claude-video-studio file layout: `studio.config.json` (app name, URL, read-only app repo path, logo); `brand/brand.md` (product, audience, CTA and a "claims table: each claim and the file in your code that proves it"); `brand/frame.md` + `src/theme.ts` (colours, fonts, radii, motion personality, end card — "scenes never hard-code hex"); `brand/sound.md`; `src/motion/` (beat timeline hooks, springs, text reveals, camera, counters, formats and safe zones); `src/kit/` (Stage/Shot, backdrop, grain, cursor, logo lockup, ported app UI); per-video `brief.md → script.md → shotlist.md → timeline.json (beats) → timeline.resolved.json → scenes/*.tsx`; a 5-second `smoke` video to test the pipeline. — [claude-video-studio README](https://github.com/rishabhsxn/claude-video-studio); [CLAUDE.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/CLAUDE.md)
- Its CLAUDE.md house rules (verbatim excerpts): "Every frame is a pure function of the frame number ... No CSS transitions/animations, tailwindcss-animate, framer-motion, setTimeout, requestAnimationFrame, `Date`, or `Math.random`"; "Time is in beats ... never hard-code frame numbers (drafts are 30 fps, finals 60 fps) and never sum durations by hand"; "One layout per format via `useFormat().pick(wide, tall)`. Never crop one format into the other"; "One display face, one UI face, one accent family ... Accent on the key word only"; "A pure opacity fade is never an enter or exit"; "headline ≥84 px and must-read text ≥44 px on a 1080 px short side; readable at 360 px wide. Scale the camera, not the font"; "9:16: keep key content out of the top 14 %, bottom 20 % and right 12 %"; "frame 0 is never empty; hook readable by 2 s; something new every 2–4 s; no hold longer than one bar without motion (micro push 1.00→1.04) ... end card ≤2 s and never static"; "Real UI only ... Never invent UI"; gates "never skip, never self-approve"; plus "Compact instructions: Keep: current slug, gate status, open critic issues, last scores, unaddressed user feedback." — [CLAUDE.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/CLAUDE.md)
- Remotion's official layout rules for agents: "You are designing a video, not a webpage. Decide what the viewer should notice first in each scene ... For 1080px-wide videos, keep key text at least 80px from the sides and 100px from the top and bottom ... Main headline: 84px; Important supporting text: 44px. Scale those values with the composition width." — [remotion-create video-layout.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-create/video-layout.md)
- Remotion markup rules: get `fps` from `useVideoConfig()` and write timing as `from={3 * fps}`; drive animation only with `useCurrentFrame()` + `interpolate()` ("CSS `transition` or `animation` will not render correctly ... Tailwind animation class will not render correctly"); use `Easing.bezier()`/`Easing.spring()`; keep `interpolate()` inline in `style` and use `scale`/`translate`/`rotate` props so Studio can edit keyframes; `output: 'perceptual-scale'` for scale animations; `Track` for successive scenes, `TransitionSeries` for overlapping transitions; scenes via `Interactive.create()` registered as connected compositions; assets in `public/` via `staticFile()`; `@remotion/media` `<Video>/<Audio>`; Zod schema for parametrised compositions (parameters.md); `calculateMetadata` for dynamic duration/props; Lottie via `@remotion/lottie`. — [remotion-markup SKILL.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/SKILL.md); [timing.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/timing.md); [multi-scene-video.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/multi-scene-video.md)
- Remotion's skill also says "Preserve user changes ... If you detect a surprising change made in the meanwhile, don't overwrite it" — relevant because Studio edits write back to code. — [remotion-best-practices SKILL.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-best-practices/SKILL.md)
- Easing/duration tokens published as starting values (motion-lab numbers.md): ease-out-expo `0.16, 1, 0.3, 1` (text/logo reveals), ease-out-quint `0.22, 1, 0.36, 1` (premium entrances), ease-in-out-quart `0.76, 0, 0.24, 1` (moves/camera), ease-in-expo `0.7, 0, 0.84, 0` (exits), ease-out-back `0.34, 1.56, 0.64, 1` (~10% overshoot pop); exits 40–50% of entrance duration; durations UI feedback 100–200 ms, UI move 200–500 ms, hero reveal 600–900 ms; stagger letters 1 frame, words 60–120 ms, list items 40–80 ms; secondary moves 50–70% of hero travel starting 100–200 ms later; springs by damping ratio ζ (1.0 no bounce, 0.7–0.85 premium, 0.4–0.6 playful) — Remotion `spring()` default (mass 1, damping 10, stiffness 100) is ζ = 0.5; beat grid frames-per-beat = fps×60/BPM, computed per beat and rounded to avoid drift; text holds ≥0.3 s per word + 0.5 s; contrast ≥4.5:1; ≤3 flashes/s. — [motion-lab numbers.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/references/numbers.md)
- claude-motion bundles "motion rules with numbers" (e.g., "`bezier(0.16, 1, 0.3, 1)` for entrances, exits at half the duration, 0.09 s between words"), a stdlib-Python procedural sound engine mastered to −14 LUFS, and "One timeline for everything. Every beat is a named timestamp in a JSON file. Scenes, sound and review all read it, so retiming the video retimes the sound and the checks with it." Reusable components: masked text reveals, rolling numbers, film grain, line boil, drifting grid background. — [claude-motion README](https://github.com/whaleyxbt/claude-motion)
- Every's scaffold: `remotion.config.ts` render defaults (h264, crf 18), `public/fonts/` for brand fonts, starter `LaunchVideo.tsx`; inputs gathered first are launch brief, brand tokens and a screen recording. — [EveryInc README](https://github.com/EveryInc/product-launch-video)
- Fonts: `@remotion/google-fonts` `loadFont()` is "type-safe and automatically blocks rendering until the font is ready"; load only needed weights/subsets; local fonts have a separate guide. — [google-fonts.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/google-fonts.md)
- Alternative engines: HyperFrames (HeyGen, HTML + GSAP → MP4, Apache 2.0) ships agent skills `/hyperframes`, `/hyperframes-cli`, `/gsap`; CLI `npx hyperframes init`, `preview`, `render` (search summary) — [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes). motion-lab's engine table: plain HTML/CSS/SVG/Canvas for one idea under ~10 s; three.js for 3D; Remotion for "series, templates, data-driven or long video"; GSAP/HyperFrames for timeline thinking in web pages. — [motion-lab SKILL.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/SKILL.md). AbubakrChan's v2 dropped GSAP/HyperFrames for "plain HTML and closed-form springs ... music-first timing ... Playwright subframes with ffmpeg motion blur". — [product-launch-motion README](https://github.com/AbubakrChan/product-launch-motion)

### Inferences
- For a marketing team: one Remotion repo with `brand/` docs + `theme.ts` tokens (colors, type scale, easing + duration tokens), `src/motion` primitives, Zod-typed composition props for data-driven variants (e.g. per-feature or per-locale), one composition per aspect ratio, and a CLAUDE.md with the render contract + banned looks + gates.
- Beat-based timelines (timeline.json) are the recurring trick for keeping picture, sound and review in sync and for retiming without breakage.

### Gaps
- No public Lottie-heavy agent workflow found beyond "Lottie only through `@remotion/lottie`". No evidence on how well agents edit existing Lottie JSON.

## 4. Common failure modes and fixes

### Takeaway
Most failures are either (a) determinism/render-contract bugs (CSS animations, timers, random, fonts not loaded, will-change blur) or (b) direction failures (generic "AI look", everything moving at once, text moving while read, too-short holds, overlaps during transitions, invented UI, cropped aspect ratios). Both are fixed by rules in the project files plus frame-level review.

### Cited Findings
- motion-lab symptom→cause→fix table (verbatim highlights): nondeterministic frames → "Clock, timer or unseeded random in the draw path" → every value a function of t, seeded RNG; "Fallback font in early frames" → "Capture started before the web font loaded" → `display=block`, await `document.fonts.ready`, set `window.__ready`; "Edges pop at a transition's end" → both layers drawn at 0/1 → draw exactly one layer at progress 0 and 1; "Wrong library parameter, silently ignored" (e.g. three.js `TextGeometry` `height`→`depth` at r163) → pin version, read that version's source; "Text shimmers while still" → snap resting text to whole pixels, render at `--scale 2`; "Text moves before it can be read" → 0.3 s per word + 0.5 s; "Everything moves at once" → one hero, others 150 ms later at 60% travel; "Banding in the GIF" → flat color or dither; sound hits late → measure with hit-check on decoded MP4; "Generic 'AI' look" → "Name each default seen in the render and add it to BANNED". — [motion-lab fixes.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/references/fixes.md)
- Remotion-specific: CSS transitions/animations and Tailwind animation classes don't render correctly; must be refactored to `useCurrentFrame()`+`interpolate()`. `interpolate()` doesn't clamp by default — add `extrapolateLeft/Right: "clamp"`. — [remotion-markup SKILL.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/SKILL.md); [timing.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/timing.md)
- Text overflow: use `@remotion/layout-utils` `measureText()`, `fitText()` (cap with `Math.min(fontSize, 80)`), `fillTextBox()` for overflow; only measure after fonts load (`waitUntilDone()`), use `validateFontIsLoaded: true`, match font props between measure and render, prefer `outline` over `border`. — [measuring-text.md](https://github.com/remotion-dev/skills/blob/main/skills/remotion-markup/measuring-text.md)
- Recharts in Remotion: `isAnimationActive={false}` and key charts by frame, else axes flicker across render tabs; "No `will-change`, `translate3d`, `translateZ`"; motion blur only in finals and only on the foreground layer. — [claude-video-studio CLAUDE.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/CLAUDE.md)
- "Never put will-change on anything the camera scales or the text renders blurry"; text swapping inside a morphing container needs its own enter/exit timing or it overlaps; loops stutter unless last frame equals first (cursor position and speed included). — [product-launch-motion prompts.md](https://github.com/AbubakrChan/product-launch-motion/blob/main/references/prompts.md)
- frame-critic's explicit failure list: "empty frame 0 · sound before the visual reads · static end card · tiny CTA at 360 px · a shot's pre-roll cutting over an unfinished exit · flat 'sticker' depth · empty 9:16 zones · double-exposed captions · lingering caret · glyph slivers at masks · orphaned sub-captions · blank handoff frames · type leaking outside its window · type crossing busy UI while the camera moves · holds longer than one bar · banned looks (lone centred title on gradient, everything fading, crossfades, corner labels, frame borders, glow on UI, particles, spins, glitches, light leaks, bounce on UI or type)". — [frame-critic.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/.claude/agents/frame-critic.md)
- "Never invent product UI labels ... This is the single biggest source of launch video cringe"; "a 16:9 clip cropped to 9:16 in post usually looks bad" — make a separate composition per aspect ratio; counters: "A bigger target number shouldn't fit in the same animation window — stretch it"; end card "one headline + CTA ... Use the landing page's actual tagline". — [EveryInc SKILL.md](https://github.com/EveryInc/product-launch-video/blob/main/.claude/skills/product-launch-video/SKILL.md)
- Audio: Claude "can't hear or watch in real time. It measures tempo, grid fit, loudness and clipping. You pick the music and the voice by ear, and you watch the drafts on your phone." — [claude-video-studio README](https://github.com/rishabhsxn/claude-video-studio). Sound hits should peak 1 frame after the picture event, 3–6 dB over the bed, verified on the decoded MP4. — [motion-lab SKILL.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/SKILL.md)
- Rough first drafts are expected: "Timing might feel off. Colors might need adjustment." Sandboxed environments may block the preview server (search summary) — [search results summarising zerofuturetech / blotato guides](https://zerofuturetech.substack.com/p/generate-videos-with-claude-code)
- Render performance: final renders ~18–19 min per format on an M1 Pro for a 30 s 60 fps film with motion blur. — [claude-video-studio README](https://github.com/rishabhsxn/claude-video-studio)

### Inferences
- Put the failure table into CLAUDE.md/skill as a growing "gotchas" list; motion-lab explicitly recommends adding each recurring fix to the render contract.
- Draft at 30 fps/half-res, final at 60 fps — only works if timing is expressed in seconds/beats, not raw frames.

### Gaps
- No systematic data on Remotion render performance tuning for agents (concurrency, `--gl` choices) beyond motion-lab's WebGL note ("use `--gl` ... several times faster than software GL" if output matches).

## 5. Giving the agent "taste"

### Takeaway
Taste is supplied by (1) a named ban list of AI-default looks, (2) numeric translations of feelings, (3) measured reference films (downloaded and analysed into technique cards), (4) a harsh fresh-eyed critic with score caps, and (5) human approval gates at brief/storyboard/animatic. Adjective-only direction ("premium", "modern") reliably produces the generic look.

### Cited Findings
- motion-lab starting BANNED list: "purple/blue gradients, glow and bloom halos, lens flares, decorative particles, sparkles and dust, turntable spins, dark void backdrops, a centered stack of every element ..., fade-and-slide-up on every element, all elements entering at once, text that moves while being read. Keep one only if GOAL requires it, and say why in the brief." Also "GOAL names what the subject does ... Effects that would fit any subject do not serve GOAL." — [motion-lab SKILL.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/SKILL.md)
- Feedback vocabulary → numbers: "Make it pop" = scale 1.0→1.08→1.0 over 6 frames, peak on the beat; "More premium" = ease-out-quint entrances, springs ζ 0.8, no overshoot on text; "It drags" = cut each hold by one beat; "Too busy" = one hero at a time, others 150 ms later at 60% travel, or remove 30% of motion; "Looks like AI" = name each default, add to BANNED, re-render; "Abrupt ending" = 36-frame hold with 2% push settling on ζ 0.8 spring. Also "Push key poses 10 to 30% further than feels right: the feed plays everything small." — [motion-lab numbers.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/references/numbers.md)
- Allowed enter/exit vocabulary (claude-video-studio): enters = "rise through a mask, grow from a source (scale 0.85→1, opacity in ≤4 frames), type-on, build (skeleton → content), card rise"; exits = "lift through a mask, get covered, get pushed, collapse into the next shot, hard cut". — [CLAUDE.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/CLAUDE.md)
- Reference libraries: motion-graphic skill ships `launch-films.csv` (125 launch films from OpenAI, Claude, xAI, Manus), `google-films.csv` (38), `teasers.csv` (25), 92 technique cards, 10 directions and a 298-transition study; it downloads and measures reference films (cuts, transitions and lengths, camera, text cards, "where the seconds go"). — [motion-graphic-skill README](https://github.com/VoMinhKhoii/motion-graphic-skill). claude-video-studio's `tools/refs.sh` uses yt-dlp for "local study only ... learn the grammar, never copy the content, and never commit or publish them". — [claude-video-studio README](https://github.com/rishabhsxn/claude-video-studio)
- Second-agent critics: frame-critic ("Be a demanding motion director, not a supportive colleague. 'No 8 without evidence.'") with criteria Hook, Readability, Motion, Pacing and variety, Brand accuracy, Sound sync, Composition, Polish and caps like "a fade used as an enter/exit/transition → max 6", "invented UI, wrong font or a second accent → max 6". — [frame-critic.md](https://github.com/rishabhsxn/claude-video-studio/blob/main/.claude/agents/frame-critic.md). Every uses 4 parallel specialist critics. — [EveryInc SKILL.md](https://github.com/EveryInc/product-launch-video/blob/main/.claude/skills/product-launch-video/SKILL.md)
- "Find the one moment only your product can deliver — give it the most screen time ... Don't spread the runtime evenly across features"; "Before/after stagger beats simultaneous. Land the 'before' first for 0.7-1s, then crash in the 'after' with a spring overshoot and a color flash." — [EveryInc SKILL.md](https://github.com/EveryInc/product-launch-video/blob/main/.claude/skills/product-launch-video/SKILL.md)
- "What makes it look expensive" rules (AbubakrChan): "One shape, never cut", "Blur content swaps", "Springs, a tiny overshoot at most", "A cursor drives everything. Real clicks with press-scale and ripple"; each rule "came from a review note on a real film". — [product-launch-motion README](https://github.com/AbubakrChan/product-launch-motion)
- A curated index of ~180 agent video skill repos, security-graded: [zhuyansen/awesome-claude-video-skills](https://github.com/zhuyansen/awesome-claude-video-skills); toolkit covering Remotion, Manim, FFmpeg: [wilwaldon/Claude-Code-Video-Toolkit](https://github.com/wilwaldon/Claude-Code-Video-Toolkit) (search summary).

### Inferences
- Rather than naming "Apple/Stripe/Linear style", practitioners get better results feeding measured frames/contact sheets from specific reference films plus a ban list; a company could maintain its own `refs/` contact-sheet library and technique cards.
- Install a third-party taste skill (motion-lab, claude-motion) alongside Remotion's official skills: Remotion's skills teach API correctness, not direction (claude-motion: "Remotion skills teach your agent the API. This teaches it taste").

### Gaps

## 6. Rendering, delivery and licensing

### Takeaway
Default Remotion output is H.264 MP4 with CRF 18 (good for social); ship one composition per aspect ratio; consider 60 fps + motion blur for finals, −14 LUFS audio, burned-in captions and a GIF. Remotion is free for individuals and for-profit companies up to 3 employees; larger companies need a Company License (Creators seats ~$25/seat/month; Automators $0.01/render with $100/month minimum, per search summaries of remotion.pro).

### Cited Findings
- Codecs: `h264` (default), `h265`, `vp8`, `vp9`, `av1`, `prores`; H.264 "Very fast" encode and "Very good" browser compatibility; AV1 not available on Lambda or Linux ARM64 GNU; hardware acceleration from 4.0.228 (cannot set CRF with it). CRF ranges/defaults: H264 1–51 default 18; H265 0–51 default 23; VP8 4–63 default 9; VP9 0–63 default 28; AV1 0–63 default 30. "Every codec has it's own range ... `23` will look very good on a H264 video, it will look terrible on a WebM video." — [Remotion Encoding Guide](https://www.remotion.dev/docs/encoding) (read from [docs source](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/encoding.mdx))
- Remotion Lambda: "fastest and most scalable way"; suited to videos "less than 80 minutes long at Full HD" (15-min AWS timeout), within AWS concurrency limits and supported regions. — [Remotion Lambda docs](https://www.remotion.dev/docs/lambda) ([source](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/lambda.mdx))
- Platform specs table (Every): X 16:9 1920×1080 or 9:16 1080×1920, max 2:20; LinkedIn 16:9 or 1:1 1200×1200; YouTube Shorts 9:16 60 s; Instagram Feed 4:5 1080×1350 60 s; Reels 9:16 90 s; TikTok 9:16 3 min. Deliverable pack: MP4 per aspect, GIF, platform caption variants. — [EveryInc SKILL.md](https://github.com/EveryInc/product-launch-video/blob/main/.claude/skills/product-launch-video/SKILL.md)
- claude-video-studio finals: "60 fps with motion blur, mastered to −14 LUFS, captions (`.srt`) and posters"; 9:16 and 16:9 from one timeline, each laid out separately. — [claude-video-studio README](https://github.com/rishabhsxn/claude-video-studio)
- License text: free for "an individual", "a for-profit organization with up to 3 employees", non-profits, and evaluation; "You are required to obtain a Company License to use Remotion if you are not within the group of entities eligible for a Free License"; buy at remotion.pro. "In Remotion 5.0, the license will slightly change" ([PR #3750](https://github.com/remotion-dev/remotion/pull/3750)). — [Remotion LICENSE.md](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)
- Pricing (search summaries of remotion.pro and Remotion v5.0 terms, not read directly): Remotion for Creators $25/seat/month, no seat minimum, for organisations making low-volume videos for themselves without automation; Remotion for Automators $0.01 per render with $100/month minimum (developers on automation projects need no seat); when both active, the $100 minimum applies and seat spend counts toward it; Enterprise from $500/month. One reviewer site's "$100/month or $1000/year" figure conflicts with the official pages. — [remotion.pro/license](https://www.remotion.pro/license); [Remotion Terms v5.0](https://www.remotion.dev/docs/terms); conflicting: [autoae.online](https://autoae.online/blog/is-remotion-free)
- Other licences in the stack: ElevenLabs free plan is non-commercial and requires attribution; ACE-Step 1.5 MIT (authors ask for AI-music disclosure); reference videos local study only; GSAP "free incl. former bonus plugins"; HyperFrames Apache 2.0. — [claude-video-studio README](https://github.com/rishabhsxn/claude-video-studio); [motion-lab SKILL.md](https://github.com/NovusEdge/motion-lab/blob/main/skills/directing-motion/SKILL.md)

### Inferences
- A marketing team at a company with >3 employees using Remotion internally for its own videos most likely fits "Creators" seats; if videos are generated by an automated pipeline (e.g., data-driven variants rendered by a script/Lambda), the Automators per-render tier likely applies. Confirm on remotion.pro before purchase.
- Remotion's own skill avoids rendering until explicitly asked; in an automated team pipeline, add explicit render commands/settings to CLAUDE.md (codec h264, CRF 18, fps, per-aspect compositions).
